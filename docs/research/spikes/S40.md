# S40: the finger heuristics against the Corne's committed table

Question: the Corne's committed `fingers` and the column-from-home-row rule disagree. Which is wrong?

## What was run

The test `test/boards/derive/heuristics.test.ts` (added in `bb86f07`, rung 21 part 1, 2026-10-16) derives each of BK's three boards from its firmware source file and compares the result with the committed `board.json`. It was re-run on 2026-10-17 on the branch of this change: 6 pass, 0 fail, 41 expectations.

## What was observed

The rule was right and the committed Corne table was one column off. The table was fixed in rung 19 (D-227). With the fix the rules reproduce the committed boards:

| Rule | Moonlander | Glove80 | Corne |
|---|---|---|---|
| Hands | 72/72 | 80/80 | 42/42 |
| Thumbs | 8/8 | 12/12 | 6/6 |
| Fingers | 64/64 | 68/68 | 36/36 |
| Rows | 5/5 | 6/6 | 3/3 |
| Mirror pairs | 36/36 | 40/40 | 21/21 |

The ledger gives the same totals (194/194 hands, 26/26 thumbs, 132/132 fingers without the Corne, 36/36 on the Corne). The first version of the rows rule merged the Glove80's six rows into one; linking each key to the key level with it in the next column fixed that. The committed Moonlander files two thumb keys (59, 60) under `lower`, and the rule calls them thumbs.

## What is still open

Only BK's three boards were checked, and all three were used to tune the rules. How well the rules do on a keyboard keyloom has not seen is not measured. The full table and caveats are in [15-open-questions.md](../../blueprint/15-open-questions.md) under "S40 and S42 results".
