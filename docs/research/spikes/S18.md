# S18: does changing the Glove80's USB serial prefix break anything of MoErgo's?

The module changes the serial number from `moergo.com:GLV80-<chip ID>` to `keyloom/<12>-<L|R>:GLV80-<chip ID>` (D-132). The question is whether anything reads the prefix. Part one is static and was done on 2026-10-15; part two needs the keyboards after S12 and is a short check.

## Static: what MoErgo's public code reads

`git grep "moergo.com:"` at the pins keyloom builds against:

| Repo | SHA | Result |
|---|---|---|
| `moergo-sc/zmk` | `ce69e85f585c724142aae37ddf8a7e019ff19e93` | `moergo.com:` appears only as the default `CONFIG_USB_DEVICE_SN` in `app/boards/arm/glove80/glove80_lh_defconfig:17` and `glove80_rh_defconfig:17` (and `GO60-` for the Go60). `usb_serial_number.c` reads `CONFIG_USB_DEVICE_SN` to fill the template; nothing parses the prefix. |
| `moergo-sc/Adafruit_nRF52_Bootloader` | `bb68c75e33c6bebaa5f770a28bd76e667b46634d` | `moergo.com` appears only in `README.md` and in `UF2_INDEX_URL` (a web address); the bootloader has its own USB descriptors and never sees the app's serial. |
| `moergo-sc/glove80-zmk-config` | `34888be8c9d9a3d5b168a502b8b191ba43b4a1f3` (the template) | `git grep -i "serial\|moergo.com:"` finds nothing; it builds the firmware and joins the halves. |

So in everything public, the prefix is a default string and not a key. The Layout Editor (`my.glove80.com`) and MoErgo's support site are closed and were not read. The template's README (`README.md:7`, `:29-35`) describes the flow as downloading a built `glove80.uf2` and flashing it "according to the user documentation", with no step that reads the keyboard.

Not found, so not claimed: whether MoErgo's Layout Editor or any support tool reads a connected Glove80's serial over WebUSB or WebHID.

## On the keyboards, after S12

Takes ten minutes. A pass is "nothing noticed".

1. **macOS keyboard identity.** Keyboard Setup Assistant and per-keyboard modifier-key settings key on vendor and product ID, not serial. After the flash: System Settings > Keyboard > Keyboard Shortcuts > Modifier Keys lists the Glove80 and keeps BK's remaps; no "Keyboard Setup Assistant" prompt appears at plug-in. Record what the list shows.
2. **Karabiner-Elements** (if BK uses it): the Glove80's per-device rules still match (its device list shows vendor `0x16c0`, product `0x27db`/`0x27d9`; its rules match on those, not on the serial).
3. **MoErgo's Layout Editor.** Open https://my.glove80.com in the browser BK uses, with the keyboard plugged in, and look for a "device" or "connect" feature. If there is none, the answer is that nothing of MoErgo's reads the serial. If there is, connect, and record whether it still sees the keyboard.
4. **Reverting is possible.** Flashing MoErgo's own firmware (the backup `.uf2`, or a Layout Editor build) restores `moergo.com:GLV80-...`. Keep that route to hand in case any of the above reacts.

Record in `S18 result` in 15-open-questions.md: the three static rows above, the outcome of 1 to 3, and whether the Layout Editor has any device feature.
