# S6: Layout Editor export, parse and compile

Run 2026-10-15 on BK's Mac. Firmware `moergo-sc/zmk@ce69e85f585c724142aae37ddf8a7e019ff19e93` (`v26.09`), template `moergo-sc/glove80-zmk-config@34888be8c9d9a3d5b168a502b8b191ba43b4a1f3`, grammar `tree-sitter-devicetree` 0.15.0.

## What was not tested

BK's real export isn't available yet, so nothing here is evidence of what the MoErgo Layout Editor emits. The fixtures are the template's own default keymap (`test/fixtures/zmk/glove80-template`, MIT, copied unchanged) and a keymap written by hand in the Layout Editor's shape (`test/fixtures/zmk/layout-editor-style`). The importer is built to tolerate: `layer_<Name>` or any node names, `display-name` or `label`, `#define LAYER_<Name> n`, hold-taps with `<&kp>, <&kp>` or `<&mo>, <&kp>`, macros, combos, overrides of `&mt` and `&lt`, comments and `\r\n`. Anything else it keeps verbatim, so it should import rather than fail. Whether it does is the open part of S6.

## (a) Parsing

The grammar parses both fixtures with no `ERROR` nodes. It gives `preproc_include`, `preproc_def`, `preproc_function_def`, nodes with `label: name`, properties and `integer_cells`. Binding cells are tokenised by keyloom (`src/firmware/zmk/cells.ts`) because the grammar reads `LC(LS(A))` as a call but `(A)` as loose tokens. A file the grammar can't read is reported with its line.

## (b) Compiling

keymaps keyloom writes from the template keymap and from the hand-written one compile unmodified against the pinned fork through the template's Docker route (`nix-build ./config`), 14–17 s per build once the image exists. The hand-written one has a modelled hold-tap with `hold-trigger-key-positions` and `hold-trigger-on-release`, macros with press, release and wait steps, combos, `&mt { tapping-term-ms }` and a `.conf`.

Things the builds showed that no document did:

- **A combo with no `layers` is on every layer.** `app/src/combo.c:151` treats an empty layer mask as active everywhere. `layers = <(-1)>` fails to compile on this fork: `BIT(-1)` is "initializer element is not computable at load time". D-048.
- **Kconfig warnings abort the build.** `CONFIG_ZMK_USB_LOGGING="x"` (a bool symbol) printed `glove80.conf:6: warning: ... Assignment ignored`, then `error: Aborting due to Kconfig warnings`. The last lines of the output say only "Configuring incomplete"; `src/firmware/zmk/locate-error.ts` finds the conf line.
- **dtc's column counts expanded text.** `devicetree error: ...glove80.keymap:89 (column 245)` for a binding on a 100-character line, because cpp has already expanded every key name. keyloom names the row, not the key.
- **`display-name` is accepted on behaviours and macros** (`behavior-metadata.yaml`), and `label` is deprecated there (a warning, not an error). keyloom writes `display-name` and reads either.
- **Unexplained, twice:** a rebuild right after a failed one printed `error: end of string reached` from Nix while evaluating the combined derivation, before any compile. Re-running the same build fine afterwards. Not reproduced on demand; the Cachix binary cache is the suspect and was not checked.
