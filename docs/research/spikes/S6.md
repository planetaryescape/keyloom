# S6: Layout Editor export, parse and compile

Run 2026-10-15 on BK's Mac. Firmware `moergo-sc/zmk@ce69e85f585c724142aae37ddf8a7e019ff19e93` (`v26.09`), template `moergo-sc/glove80-zmk-config@34888be8c9d9a3d5b168a502b8b191ba43b4a1f3`, grammar `tree-sitter-devicetree` 0.15.0.

## What was not tested

**Superseded below ("Result with BK's own config").** This section describes the first run, before BK's config was available. BK's real export wasn't available yet, so nothing here is evidence of what the MoErgo Layout Editor emits. The fixtures are the template's own default keymap (`test/fixtures/zmk/glove80-template`, MIT, copied unchanged) and a keymap written by hand in the Layout Editor's shape (`test/fixtures/zmk/layout-editor-style`). The importer is built to tolerate: `layer_<Name>` or any node names, `display-name` or `label`, `#define LAYER_<Name> n`, hold-taps with `<&kp>, <&kp>` or `<&mo>, <&kp>`, macros, combos, overrides of `&mt` and `&lt`, comments and `\r\n`. Anything else it keeps verbatim, so it should import rather than fail. Whether it does is the open part of S6.

## (a) Parsing

The grammar parses both fixtures with no `ERROR` nodes. It gives `preproc_include`, `preproc_def`, `preproc_function_def`, nodes with `label: name`, properties and `integer_cells`. Binding cells are tokenised by keyloom (`src/firmware/zmk/cells.ts`) because the grammar reads `LC(LS(A))` as a call but `(A)` as loose tokens. A file the grammar can't read is reported with its line.

## (b) Compiling

keymaps keyloom writes from the template keymap and from the hand-written one compile unmodified against the pinned fork through the template's Docker route (`nix-build ./config`), 14–17 s per build once the image exists. The hand-written one has a modelled hold-tap with `hold-trigger-key-positions` and `hold-trigger-on-release`, macros with press, release and wait steps, combos, `&mt { tapping-term-ms }` and a `.conf`.

Things the builds showed that no document did:

- **A combo with no `layers` is on every layer.** `app/src/combo.c:151` treats an empty layer mask as active everywhere. `layers = <(-1)>` fails to compile on this fork: `BIT(-1)` is "initializer element is not computable at load time". D-048.
- **Kconfig warnings abort the build.** `CONFIG_ZMK_USB_LOGGING="x"` (a bool symbol) printed `glove80.conf:6: warning: ... Assignment ignored`, then `error: Aborting due to Kconfig warnings`. The last lines of the output say only "Configuring incomplete"; `src/firmware/zmk/locate-error.ts` finds the conf line.
- **dtc's column counts expanded text.** `devicetree error: ...glove80.keymap:89 (column 245)` for a binding on a 100-character line, because cpp has already expanded every key name. keyloom names the row, not the key.
- **`display-name` is accepted on behaviours and macros** (`behavior-metadata.yaml`), and `label` is deprecated there (a warning, not an error). keyloom writes `display-name` and reads either.
- **Unexplained, twice:** a rebuild right after a failed one printed `error: end of string reached` from Nix while evaluating the combined derivation, before any compile. Re-running the same build fine afterwards. Not reproduced on demand; the Cachix binary cache is the suspect and was not checked.

## Result with BK's own config (2026-10-15)

**What was run.** BK's Glove80 config is not a Layout Editor export. It lives in his own config repo, `bhekanik/glove80-zmk-config` at `93b6ac8`, branch `42-key-map`. Its `glove80.keymap` and `glove80.conf` were imported, regenerated and built with keyloom's pinned toolchain (`moergo-sc/zmk` `ce69e85`, `v26.09`). Evidence is in the build's `evidence/glove80/bk-config/` folder; its repository paths are not reproduced here.

**What was observed.**

- Import: succeeds with seven warnings, for behaviours kept as written (magic, `layer_on_hold` hold-taps, and the `rgb` and `bt` macros).
- Import, generate, import gives an identical layout (`rt.json`).
- Building BK's original keymap unmodified gives a UF2 that is byte-identical to the one BK's own GitHub Action built: sha256 `767243265a93e1d829c15765282532397ab05f08d04f0c7bb8a0f30173475463`. Checked again on 2026-10-17 by hashing `original.uf2` and `ci/glove80.uf2`. The Action used MoErgo's `main` at `4b2f3b9` and keyloom pins `ce69e85`; the ledger notes the bytes are the same anyway.
- keyloom's regenerated keymap builds to different bytes (`label` becomes `display-name`, node order, one include). Its behaviour matches in the ZMK emulator (D-075): an every-key sweep (130 reports) and ten home-row holds (40 reports) are identical for the original and the regenerated keymap. Checked again on 2026-10-17 by comparing the report lists in `eq-everyKey-*.json` and `eq-holds-*.json`.

**What is still open.**

- Nothing in this run came from MoErgo's Layout Editor, so what the Editor itself emits is still unobserved. Q9 is answered by the config repo being the source.
- Equivalence is emulated, not typed. The regenerated keymap's byte difference was not flashed. The Glove80 on BK's desk runs keyloom's build, flashed in [S8](S8.md).
- The unexplained Nix "end of string reached" error above was seen twice and has not recurred in the ledger.
