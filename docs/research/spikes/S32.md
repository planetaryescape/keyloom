# S32: what kanata sees for fn, the function row, Escape, Touch ID and the arrows

A runbook, not a result. Nothing here has been run. It needs BK at the keyboard and the setup from [S30](S30.md) steps 1 to 4. It decides the board's key list for the F-row and fn, which the generator currently writes as `f1` to `f12` and `fn`.

## Capture

Write a capture config with no remapping and run kanata at debug level against the built-in keyboard only:

```sh
cat > /tmp/capture.kbd <<'CFG'
(defcfg
  process-unmapped-keys yes
  macos-dev-names-include ("Apple Internal Keyboard / Trackpad")
)
(defsrc a)
(deflayer base a)
CFG
sudo kanata -d -c /tmp/capture.kbd
```

Stop it with Left Control + Space + Escape when done. Save the log without private text (type only the keys named below).

## Press, in order, and write down what kanata logs

1. fn/globe, alone, then fn with each of F1 to F12.
2. F1 to F12 alone, with the system setting "Use F1, F2, etc. keys as standard function keys" off, then on.
3. Escape.
4. The four arrows, then fn with each arrow.
5. Touch ID: press it. Expected from the research: nothing (it is a separate device); record whether kanata logs anything.
6. Caps Lock, Left and Right Command, Option and Control.

For each, record the name kanata prints (it is the name `kanata --list` and the docs use), whether macOS still does its own thing (brightness, volume, Mission Control), and whether the key can be both remapped and still reach macOS.

## What it decides

- If F1 to F12 arrive as `f1` to `f12`, the board's list stands. If they arrive as brightness and media names (`brdn`, `brup`, `mctl`, `sls`, `dtn`, `dnd`), `physicalKeys` in `boards/apple/macbook-ansi/board.json` changes for those positions and the identity layout stops sending F-keys for them. Open issue `jtroo/kanata#975` ("F-row key get override on MacOS") is the known risk.
- If fn can't be remapped without losing the Globe function, the layout keeps it as the kept `fn` binding and the editor says it can't be changed.
- BK's imported F6 to F13 mapping depends on this: it is imported as a plain key remap and the report says so.
