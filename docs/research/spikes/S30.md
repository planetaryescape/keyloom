# S30: kanata on the MacBook's built-in keyboard only

A runbook, not a result. Nothing here has been run. It needs BK at the keyboard and one administrator password, so the orchestrator runs it with him present. The question is in [../../blueprint/15-open-questions.md](../../blueprint/15-open-questions.md): do kanata 1.12.0 and driver 6.5.0 work together on BK's Mac15,9, taking only the built-in keyboard?

Keep the Moonlander plugged in as the second keyboard for the whole run. It is the way out if the built-in one stops typing.

## Before

```sh
keyloom doctor
```

Expected on BK's Mac today (observed 2026-10-16, `evidence/rung20/doctor-real-mac.txt`): kanata not installed; driver 6.5.0 (protocol 5) fine; Karabiner-Elements 15.7.0 with a warning not to upgrade; the built-in keyboard present as "Apple Internal Keyboard / Trackpad"; no LaunchDaemon; nothing on port 5829.

## 1. Install kanata 1.12.0

```sh
brew install kanata
kanata --version
```

Expected: `kanata 1.12.0`. Homebrew's formula was at 1.12.0 on 2026-10-15 (`brew info kanata`).

## 2. The driver daemon

With Karabiner-Elements running, it manages `Karabiner-VirtualHIDDevice-Daemon`. BK's Karabiner services weren't running on 2026-10-15, so start the daemon by hand for this test (source: `docs/setup-macos.md` step 2 at `jtroo/kanata@02242ef`):

```sh
sudo "/Library/Application Support/org.pqrs/Karabiner-DriverKit-VirtualHIDDevice/Applications/Karabiner-VirtualHIDDevice-Daemon.app/Contents/MacOS/Karabiner-VirtualHIDDevice-Daemon" &
sudo launchctl list | grep org.pqrs
```

Expected: a line for the daemon. kanata's docs name driver v6.2.0 as the supported one and say newer is "not guaranteed"; BK has 6.5.0, which speaks the same protocol (5), so this step is where that is confirmed or not.

## 3. See the keyboard

```sh
sudo kanata --list
```

Expected: a list that includes `Apple Internal Keyboard / Trackpad` and BK's external boards. Record the exact lines; the device matcher is an exact string compare.

## 4. Permissions

macOS shows Input Monitoring and Accessibility prompts for the kanata binary. Allow both in System Settings, Privacy & Security. `kanata --macos-request-permissions` asks macOS to list it. keyloom can't read these grants, so note what BK had to click.

## 5. Run keyloom's identity config in the foreground

```sh
keyloom remap setup
sudo kanata -c "$HOME/Library/Application Support/kanata/keyloom.kbd" -p 127.0.0.1:5829 --release-grab-on-lock
```

`keyloom remap setup` writes the plist and an identity `keyloom.kbd` (nothing remapped). Expected: kanata logs "starting", sleeps 2 seconds, then runs. The built-in keyboard types normally. The Moonlander still types normally.

Pass checks, each one observed:

1. Type on the built-in keyboard: every key works.
2. Type on the Moonlander: unchanged.
3. In another terminal: `printf '{"Hello":{}}\n' | nc 127.0.0.1 5829` prints a `HelloOk` line with `"version":"1.12.0"`.

## 6. The exit chord

Hold Left Control + Space + Escape on the built-in keyboard. Expected: kanata exits, and the foreground command returns. Then:

```sh
keyloom remap confirm-exit-chord
```

This is what lets auto-apply turn on. Run it only after seeing kanata stop.

## 7. Apply

Start kanata again as in step 5, then import BK's Karabiner rules into a layout (read-only, step in [S31](S31.md)) or use any MacBook layout, and:

```sh
keyloom sync <layout>
keyloom --format json sync status
```

Expected: `synced ... kanata reports it loaded`, and `last_sync.timings_s.flash` well under a second. Change a home-row timing in the editor, press Apply, and type with it. Record the time from Apply to the keyboard changing.

## 8. The daemon

```sh
keyloom remap doctor
```

Run the root command it prints, once. Then:

```sh
sudo launchctl print system/dev.keyloom.kanata | head -20
```

Expected: the service is loaded and running. Hold the exit chord again: kanata stops and, because the plist's `KeepAlive` is `SuccessfulExit: false`, launchd leaves it stopped. Confirm with `sudo launchctl print system/dev.keyloom.kanata | grep -i state`.

Lock the screen (Control + Command + Q) and type the password: with `--release-grab-on-lock` the lock screen sees a plain keyboard.

## Pass and fail

Pass if the built-in keyboard is remapped, the external boards are not, the chord stops kanata, a reload with `wait` returns ok, and the lock screen works. Fail means kanata 1.12.0 and driver 6.5.0 don't work together, and Karabiner-Elements goes first (D-231).

## Rollback

```sh
sudo launchctl bootout system/dev.keyloom.kanata
sudo rm /Library/LaunchDaemons/dev.keyloom.kanata.plist
```

Or, with kanata still running and no sudo: `keyloom remap disable`. Hold Left Control + Space + Escape if the keyboard misbehaves. The Moonlander is the last resort.
