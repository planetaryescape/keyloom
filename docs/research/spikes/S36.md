# S36: the 77 keys, their order and their widths on BK's MacBook

A runbook, not a result. Nothing here has been run. `boards/apple/macbook-ansi/geometry.json` is hand-authored from Apple's standard ANSI notebook proportions and says `verified: false`; `keyloom boards check` warns about that until this is done. It needs BK at the keyboard, after [S32](S32.md).

## 1. The expected order

```sh
keyloom boards show apple/macbook-ansi
```

prints the 77 positions as keyloom numbers them: reading order, left to right and top to bottom, ending with the arrow cluster as Left, Up, Down, Right. The expected key at each position is `physicalKeys` in `board.json`.

## 2. Press every key under kanata

Use the capture config from [S32](S32.md). Press each key once in keyloom's order and write down the name kanata logs. Pass if all 77 names match `physicalKeys` through the kanata names in `src/layout/keycodes.ts`, with `fn` for the globe key.

## 3. Check the widths

Measure against Apple's published layout or a ruler on the keyboard, in key units (one unit is the pitch of a letter key). Expected: every row sums to 14.5 units. The function row is Esc 1.5 plus twelve keys, with the Touch ID key (not a position) filling the last unit. Left and Right arrows are full height and Up and Down are half height, stacked. Pass if each key's x and width are within 0.05 units.

## 4. Record

If everything matches, set `source.verified` to `true` in `geometry.json`, and the `boards check` warning goes away. If a key is out of order or a width is off, correct `geometry.json` and `board.json` together and re-run `keyloom boards check boards/apple/macbook-ansi`. An ISO MacBook is out of scope (rung 20 leaves it out).
