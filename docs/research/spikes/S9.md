# S9: BK's unchanged Moonlander layout, built and flashed by keyloom

Question: does a no-change keyloom build of BK's Oryx layout behave like his Oryx firmware?

## What was run

All on 2026-10-15, with evidence under the build's `evidence/s9-reva/` and `evidence/flash-handsfree/` folders.

1. **Round trip.** keyloom imported BK's Oryx source (`QxKPz`, revision `zLQ3Md`), generated source with no change and built for `reva` in Docker. The result is byte-identical to the build of Oryx's own source: sha256 `ccd90fdeda0a7f5e7c0017d1b5c8a9585fa2f08faeb341859ba05183d94a43fe`, 67,268 bytes. A gated Docker test now pins this for `reva` and pins `fcceb9…` for `revb` (D-070 in [14](../../blueprint/14-decision-log.md)).
2. **First flash.** A build with keyloom's marker and bootloader command (`bld_01M4ZXEY4HY9E2DAK6KN9QYHCR`, 67,336 bytes) was flashed after BK put the board in its bootloader during a 30 minute wait. Flash `fl_01M4ZY2NCKZ7BRW1KDMTM1SPC0`, 14:04 to 14:19Z, result `Verified: the keyboard is running build bld_01M4ZXEY4HY9E2DAK6KN9QYHCR`. An earlier attempt timed out at the then 2 minute wait, with nothing flashed.
3. **Hands-free flash.** The next build (`bld_01M4ZZ1H022KJ6QM16CX1F9SW6`) went on with no keypress at 14:22Z: keyloom restarted the keyboard into its bootloader over raw HID, wrote it and verified the build.
4. **A change and its undo.** One key change (F16 moved to a Command-Shift key on layer 1) was built, checked in the QMK emulator, flashed hands-free and later undone with `keyloom undo`. The layout JSON after the undo equals the original import (`hw/original.json` against `hw/after-undo.json`, compared again on 2026-10-17). Recorded in the build ledger, not re-checked: the emulator showing the key back as F16, and the reflash verifying. The first hands-free attempt in this step failed with "raw HID interface wasn't found" and flashed nothing; the lookup now retries (`31b69b6`).

## What was observed

The flow works end to end on BK's Moonlander, including the verified marker, with no keypress after the first flash.

BK typed on the keyloom build the same day and said "typing on the moonlander works". Recorded in the build ledger, not re-checked: that sentence is the only record of the typing check.

## What is still open

- Tap-hold feel, macros and RGB were not compared against the Oryx firmware one by one. A difference BK notices later reopens S9.
- BK did not report trying the moved Command-Shift key before the undo.
- Which Moonlander revision this was is S1, unresolved. The build was `reva`.
