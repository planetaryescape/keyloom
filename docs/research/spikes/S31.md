# S31: kanata next to Karabiner-Elements

A runbook, not a result. Nothing here has been run. It follows [S30](S30.md) and needs BK present. The question: with Karabiner ignoring the built-in keyboard, does kanata's output arrive once, and do BK's external boards and Karabiner's other rules still work?

## Before

BK's Karabiner config is `~/.config/karabiner/karabiner.json`, a symlink into his dotfiles. keyloom reads it and never writes it. Import it read-only:

```sh
keyloom import --board apple/macbook-ansi --name macbook ~/.config/karabiner/karabiner.json
```

Expected (observed 2026-10-16): 2 layers of 77 keys, the hold-taps, combos and key remaps from his rules, and the one switched-off rule listed as not imported. It prints the edit below.

## 1. Apply the edit

The importer prints text like this for BK to add to the profile's `devices` array in the dotfiles copy of `karabiner.json`:

```json
{
  "identifiers": { "is_keyboard": true, "product_id": 0, "vendor_id": 0 },
  "ignore": true
}
```

The identifiers are what `ioreg` shows for the built-in keyboard. They are not confirmed. With Karabiner-Elements running:

```sh
karabiner_cli --list-connected-devices
```

If the built-in keyboard's `vendor_id` or `product_id` differ from 0, use what it prints. Record the output. BK applies the edit himself and keyloom doesn't touch the file.

## 2. Run both

Start Karabiner-Elements, then kanata as in [S30](S30.md) step 5 with BK's imported layout applied (`keyloom sync macbook`). Open Karabiner's EventViewer.

Pass checks:

1. Press `a` on the built-in keyboard in a text field: one `a`, not two. In EventViewer, the key appears from the virtual keyboard once.
2. Hold `f` for over 300 ms: Command is held (the imported home-row mod). Tap `f`: `f`.
3. Hold Space, press `h`, `j`, `k`, `l`: the arrows (the imported navigation layer). Tap Space: a space.
4. Press `w` and `e` together: `+` (shift and `=`).
5. On the Moonlander, type: Karabiner's own rules for it are unchanged. BK's config already ignores both external boards.
6. Karabiner's Settings window still opens, and its menu-bar item can be used.

## Pass and fail

Pass if output arrives once, the imported behaviours work, and the external boards are unchanged. Fail if input is doubled or the built-in keyboard is grabbed by both: then Karabiner is not ignoring it (check the identifiers) or the two can't share the driver. Record which.

## Rollback

Remove the `devices` entry BK added; Karabiner takes the built-in keyboard back. Then `keyloom remap disable` or stop the daemon as in S30. His Karabiner rules were never deleted.

## Not decided here

An upgrade of Karabiner-Elements to 16.x installs driver 8.5.0 (protocol 7), which kanata 1.12.0 can't use. Don't upgrade during this spike. `keyloom remap doctor` warns about it.
