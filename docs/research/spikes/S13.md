# S13: the `keyloom-zmk` module on BK's Corne

Runbook for the orchestrator to run with BK, after S12 has passed on the Glove80. Written 2026-10-15; nothing here has been run on hardware. The Corne builds with the module on ZMK v0.3.0 (`zmkfirmware/zmk@edf5c08`, the `zmk-build-arm` image pinned in `boards/foostan/corne/board.json`) for both halves; the evidence is in `evidence/rung12/` (`corne-bld_*.zip`, `corne-halves/`, `module-in-image.txt`).

It settles the questions in [15-open-questions.md](../../blueprint/15-open-questions.md):

1. Are BK's controllers nice!nano v2 (`INFO_UF2.TXT` on the boot drive)? Nothing so far has looked at the hardware; `board.json` assumes it.
2. Does the module work there: a serial port on each half, a 1200-baud touch into the bootloader, the left half's relay to the right?
3. Does `keyloom flash` flash the two halves one after the other (they both mount as `NICENANO`), matched by marker?
4. What are the Corne's USB vendor and product IDs while it runs? Without them `keyloom doctor` can't show a half that runs older firmware, and the Corne can't tell a Glove80's port from its own except by the rule in D-134.

## Before touching the keyboard

The nice!nano's bootloader is entered by double-tapping the reset button, with the half's cable in. It reads the double tap before the app starts, so it works whatever the firmware is. The boot drive is `NICENANO`.

Both halves present one volume name and take one family ID (`0xada52840`), so the bootloader **will accept the left image on the right half**. Only one half should be in its bootloader at a time, and the half keyloom asks for is the one that must be. During the manual first flash, leave the other half unplugged.

Back up what is on each half. The Adafruit bootloader serves `CURRENT.UF2` on the drive:

```
# plug in one half, double-tap its reset; then
ls /Volumes/NICENANO                                  # INFO_UF2.TXT, INDEX.HTM, CURRENT.UF2
cat /Volumes/NICENANO/INFO_UF2.TXT                    # Model, Board-ID: record both
mkdir -p ~/corne-backup && cp /Volumes/NICENANO/CURRENT.UF2 ~/corne-backup/<left|right>-current.uf2
```

Expected for question 1: `Model: nice!nano` and `Board-ID: nRF52840-nicenano` (`bl-ada@c67f0bc` `src/boards/nice_nano/board.h:51-57`). If it says anything else (a Supermini, a `nice!nano v1`, a Pro Micro clone), the board file's `board: nice_nano_v2` and volume are wrong for BK's Corne; stop and tell the author. Eject nothing: leave the drive and press reset once to leave the bootloader.

While each half runs its present firmware, read its USB IDs (question 4):

```
ioreg -p IOUSB -w0 -l | grep -B2 -A12 -i "corne\|nice"       # idVendor, idProduct, "USB Product Name", serial
system_profiler SPUSBHostDataType | grep -B3 -A10 -i "corne\|nice"
```

Record the vendor and product ID of each half (the ZMK default is `0x1d50:0x615e`; a Corne keymap can change it). If the two halves show different IDs, record both.

## 1. Import and build (no hardware)

BK's real Corne keymap is not in this repository. Use his, or the test fixture:

```
KL="bun /Users/bhekanik/code/planetaryescape/.worktrees/keyloom-r12/src/cli/main.ts"
$KL import --board foostan/corne <his corne.keymap or test/fixtures/zmk/corne> --name corne
$KL build corne --format json
```

The first build downloads Zephyr (about 2 GB) and takes several minutes; later ones take about three. Expected in the build log: `keyloom: the firmware carries keyloom's hands-free module (build key <12>)`, then `corne_left` and `corne_right` sizes (about 430 KB and 350 KB in the rung's run). The artifact is a `.zip` with `left.uf2` and `right.uf2`.

## 2. The first flash, by double-tap

Plug in **only the left half**. Run:

```
$KL flash --layout corne --format json
```

Expected on stderr: `keyloom is checking ...`, then `keyloom couldn't restart the left half by itself: no keyloom serial port was found for it, so it needs its bootloader key this once. Flash the left half (1 of 2). Plug in the left half and double-tap its reset button. keyloom waits 2 minutes.` Double-tap reset. It writes, then waits up to 45 s for `keyloom/<12>-L` to come back.

Then: `Flash the right half (2 of 2)`. Unplug the left half, plug in the right half, double-tap reset. It verifies `keyloom/<12>-R`. **When the verification of the right half runs, both halves should be on their cables**: the left half is not needed for it, but plug both in now for the rest of the spike.

Expected result: `Verified: the left half is running build bld_..., and the right half is running build bld_....`

Pass requires that each half had the right image: the left half is the central (it types over Bluetooth to the Mac, and the right half's keys arrive through it). Type on both halves.

| Seen | Meaning | Do |
|---|---|---|
| Right half's keys do nothing after the flash, left works | The right half got the left image, or the halves lost their pairing | Re-flash the right half alone. If it repeats, reset both halves' Bluetooth settings (the ZMK `settings_reset` firmware) and report |
| `didn't come back within 45 seconds` | No port after the flash: the module's CDC interface is not enumerating on this controller | `ioreg` the half and save it |
| `came back with <hex>` and no `keyloom/` | The module's serial override did not take effect | `ioreg` the serial; it should be `keyloom/<12>-L:<16 hex>` |

## 3. Hands-free, one half after the other

With both halves on cables and the Mac connected to the left half over USB:

```
ls /dev/cu.usbmodem*                                  # two ports
ioreg -p IOUSB -w0 -l | grep -i "USB Serial Number" | grep keyloom
$KL doctor --format table | grep -i corne
$KL build corne --format json
time $KL flash --layout corne --format json
```

Expected: serials `keyloom/<12>-L:<16 hex>` and `keyloom/<12>-R:<16 hex>`, the two chip IDs different. doctor says `keyboard foostan/corne left half: running keyloom build <12> ...` and the same for the right half.

During the flash: stderr shows `keyloom is restarting the left half into its bootloader. Don't touch the keyboard.`, the writing message, the `checking it came back` message, then the same for the right half. In the flash log: `closing <port> at 1200 baud restarts it into its bootloader`, then `NICENANO appeared`, `NICENANO unmounted; the left half is flashed`, and only then the right half's touch, on a different port. The order proves the second half was not restarted while the first was mounted.

**Pass:** `succeeded`, `Verified` for both halves, typing works on both. Run it twice.

| Seen | Meaning | Do |
|---|---|---|
| The log touches the same port twice, or a port that is not a Corne's | A matching failure | Stop. Save the log: the marker or ID matching is wrong |
| `more than one Corne left half is attached` | Two ports carry `-L`: another keyloom ZMK board, or a stale port | Unplug the other board |
| `NICENANO is already mounted` | A half was left in its bootloader | If it is the half keyloom wants, fine; if you cannot tell which half it is, press its reset once and rerun |

## 4. The relay on the Corne

```
stty -f /dev/cu.usbmodem<left> 1201     # the left half's port
sleep 4; ls /Volumes | grep NICENANO
```

Expected: `NICENANO` appears (the right half), the left half keeps typing. Recover by pressing the right half's reset once. As in S12: if `stty` rejects 1201, record the text. Run it a second time to prove the rate was reset.

## 5. Both boards on the desk

With the Glove80 (running keyloom's firmware, S12 passed) plugged in as well, repeat step 3's `keyloom flash` for the Corne. **Check the flash log: no `/dev/cu.usbmodem` that belongs to a Glove80 half is touched** (its serials end `:GLV80-`). The Glove80's halves carry `keyloom/<12>-L` and `-R` too, so only the USB-ID rule stops the Corne from taking them (D-134). Then flash the Glove80 once and check the Corne's halves are not touched.

## 6. Record

Corne `INFO_UF2.TXT` for both halves; the USB IDs; the serials and the chip IDs; build IDs; flash times for step 3; the outcomes of steps 4 and 5. Then add `usbVendorId` and `usbProductId` for each half to `boards/foostan/corne/board.json` (`flash.handsFree`), so doctor can see a half that runs older firmware and so the Corne can no longer take another board's port by default.

## Failure playbook

| Situation | Action |
|---|---|
| A half does not type | Double-tap reset and copy its `CURRENT.UF2` backup to `NICENANO` |
| The halves do not talk to each other | Flash both with ZMK's `settings_reset` for `nice_nano_v2`, then the keyloom build again |
| The drive does not appear after a touch | Double-tap reset by hand. The module's polling thread is not running, or USB is not up on that half |
| A half stays in its bootloader | Press reset once, or unplug and replug |
