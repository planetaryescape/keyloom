# S21: per-key, per-layer colours on the Glove80

Run 2026-10-15 on `rung19/cross-board` from `898dec6`. The sources are local clones at the SHAs named below, plus GitHub's API for one pull request.

## Question

Can MoErgo's ZMK fork at `ce69e85f585c724142aae37ddf8a7e019ff19e93` (tag `v26.09`, the revision `boards/moergo/glove80/board.json` builds) give each key its own colour on each layer, the way the Moonlander's ledmap does (D-190)?

## Result

No. Nothing in that revision can show a colour per key, and BK's Glove80 cannot do what the Moonlander does without different firmware.

| Finding | Source |

## What this decides

keyloom does not model Glove80 lighting (D-194 stands, now with its evidence), and says so as a fact of the board: `board.json` carries a `limits.lighting` sentence, the agent and the validator quote it, and a request to copy colours onto the Glove80 ends in that sentence with nothing proposed (D-224, D-225).

Supporting it would mean pinning a community fork in place of MoErgo's tree for the Glove80 build, with a pull request that has been open since 2024-12-30 and targets a different base than the one keyloom builds. That is BK's call, not a default (Q24).
