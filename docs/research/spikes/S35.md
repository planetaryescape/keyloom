# S35: importing a Karabiner file into the MacBook layout

Run 2026-10-16 on `rung20/macbook-kanata`. The repo is public, so the fixture is synthetic: `test/fixtures/karabiner/synthetic-karabiner.json` has the same patterns as BK's own file with different keys and names. BK's real `~/.config/karabiner/karabiner.json` was imported once, read-only, outside the repo; its summary is kept with the rung's evidence, not here, and the file's modification time was unchanged.

## Result

Yes, for these patterns. `test/firmware/kanata/karabiner.test.ts` pins the chain karabiner.json, layout, `keyloom.kbd`, `kanata --check`, with golden files in `test/fixtures/kanata/`.

| In Karabiner | In keyloom |
|---|---|
| A Space rule that sets a variable while held, with sibling keys under a `variable_if` condition | Space is a hold-tap onto a layer holding those keys, profile `tap-hold-press`, 1000 ms |
| Home-row hold-taps ("a roll is a tap", 250 ms) | hold-taps on those keys, profile `tap-hold-tap-keys`, 250 ms |
| Two keys held as Hyper | hold-taps holding Control, Shift, Option and Command, same profile |
| `simultaneous` combos, 40 ms | combos with the same keys, outputs and threshold |
| `simple_modifications` and `fn_function_keys` | key remaps (beyond the brief's list: exact, and BK's file uses both) |
| A rule switched off, and a rule that clicks the mouse | listed as not imported |

Nothing was dropped. A rule is imported whole or not at all, and the tests show a shell-command rule and a half-readable rule staying in Karabiner. The edit that stops Karabiner grabbing the built-in keyboard is printed as text.

## Not checked

The edit's identifiers (vendor 0, product 0) come from `ioreg` and are unconfirmed: Karabiner's services weren't running, so `karabiner_cli --list-connected-devices` couldn't be read (S31). How imported timings feel on the keyboard is untested.
