# S51: the Glove80's key stream, both halves, in order

The build half is done; the hardware half is a runbook for the orchestrator with BK at the keyboard. Nothing below has run on a keyboard: keyloom's tests never open a real serial port, and the worker that built this did not stream from BK's Glove80.

## What is already proven (2026-10-16, no hardware)

- `firmware/zmk/keyloom-zmk/src/typing.c` compiles and behaves as specified when driven on the host: `test/firmware/zmk/typing-c.test.ts` (off by default, the handshake, the 10 minute limit, the quiet host, a closed port, queue overflow, split commands).
- It builds into the hands-free Glove80 (MoErgo's Nix image, `moergo-sc/zmk@ce69e85`) and the Corne (ZMK's west image): the Glove80 UF2 carries the module's `KLTYPE START` and `E %u %u %u %u` strings, and of the Corne's two images exactly one does (the central). Log: `evidence/rung22/zmk-build.log`.
- 1200 and 1201 baud touches are untouched in the code: `handsfree.c` is unchanged and `typing.c` never sets the line coding (the host sets 115200 first).

## What needs the keyboard

Does `uart_irq` receive the host's commands and does `uart_poll_out` keep up on the Glove80's USB serial; are the two halves' keys in order on one clock; what does the split cost.

Setup. Flash a hands-free build that has the stream with `keyloom sync <layout>`. The Glove80 must be connected by USB on the left half (the central); the probe finds the port by the build marker's `-L`.

### 1. It answers, both halves (2 minutes)

```sh
bun scripts/lab-probe.ts zmk --seconds 30
```

Press a key on each half. Pass if left-half keys print `source 255` and right-half keys print `source 0`, with the numbers the editor shows (position plus one), a press and a release each.

### 2. Order across the split (3 minutes)

Type a metronome of alternating hands at about 6 keys a second for 20 seconds: left, right, left, right. Pass if the printed sources strictly alternate. Then press one left and one right key as nearly together as you can, 30 times; the order the probe prints may differ from your intent but must never put a key's release before its press.

### 3. Split latency (5 minutes)

A peripheral key's time is when the central received it, so its latency adds to its timestamps. Type left-right alternations at a steady pace for 30 seconds, as above. For the printed events, take the median gap from a left press to the next right press (L to R) and from a right press to the next left press (R to L). If the right half's events are late by d, then L to R is longer by d and R to L shorter by d, so d is half the difference of the two medians. Record d. Anything under about 15 ms is below what home-row-mod timing can see; more means the lab's timings for right-hand keys are shifted and the runbook for S53 should say so.

### 4. It stops by itself (6 minutes)

a. Closed port. `bun scripts/lab-probe.ts zmk --no-stop`. It exits at once and the port closes (DTR low), which ends the stream silently. Run the probe again right away. Pass if it connects.

b. Stalled host. Run `bun scripts/lab-probe.ts zmk --seconds 120`, then `kill -STOP <pid>`, wait 6 seconds, `kill -CONT <pid>`. Pass if it reports `ended by the host stopped answering`.

c. The limit. `bun scripts/lab-probe.ts zmk --seconds 700`. Pass if it reports `ended by the 10 minute limit` at about 10:00.

### 5. The restart triggers still work

With the lab idle, run `keyloom flash --reboot-only --board moergo/glove80` (this is BK's call: it restarts the half into its bootloader, after which it must be flashed or unplugged). Pass if the half restarts as it did before the stream existed. Do this once, last.
