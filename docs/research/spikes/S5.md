# S5: Building the Moonlander from ZSA's fork in Docker

Run 2026-10-15 on BK's Mac (Docker 28.4.0, arm64), against `zsa/qmk_firmware` `93b2b9ec3368f86c5eb5a2e3f934049f8daef885` (branch `firmware25`).

## Result: both revisions build from BK's unchanged Oryx source

| Target | Exit | Wall time | Output |
|---|---|---|---|
| `zsa/moonlander/reva:oryxs3` | 0 | 101 s | `zsa_moonlander_reva_oryxs3.bin`, 67,268 bytes |
| `zsa/moonlander/revb:oryxs3` | 0 | 110 s | `zsa_moonlander_revb_oryxs3.bin`, 69,512 bytes |

The image was already pulled when these ran, so times are for a warm image with a cold `.build/`. The keymap folder was the S3 fixture copied verbatim into `keyboards/zsa/moonlander/keymaps/oryxs3/`.

The binaries are not byte-identical to Oryx's (69,796 and 72,000 bytes). Oryx builds with git and version information we skip (`SKIP_GIT=1`), and with a different keymap name. Whether the firmware *behaves* the same is S9, which needs BK's keyboard.

## The command keyloom must run

```
docker run --rm --user "$(id -u):$(id -g)" -w /qmk_firmware \
  -v <checkout>:/qmk_firmware -e SKIP_GIT=1 -e MAKEFLAGS=-j4 \
  ghcr.io/qmk/qmk_cli@sha256:b7d7fa8fb4432b569931de5ad59098cb788f440ed61a62c5126746b71aee0f4a \
  make zsa/moonlander/<reva|revb>:<keymap>
```

## Findings that change the blueprint

1. **keyloom can't call `util/docker_build.sh`.** It's a 3-line wrapper around `util/docker_cmd.sh`, which runs `docker run --rm -it …`. The `-it` needs a terminal, so keyloom calls `docker run` directly without it.
2. **Pin the image by digest.** `docker_cmd.sh` uses `ghcr.io/qmk/qmk_cli` with no tag. keyloom pins `sha256:b7d7fa8f…`, the digest of `latest` pulled on 2026-10-15, in the board definition.
3. **The submodules a Moonlander build needs** are `lib/chibios`, `lib/chibios-contrib`, `lib/printf`, `lib/lufa` and `modules/zsa`, which is `zsa/qmk_modules` at `13890cd7856175de20798689d15ba6a46bf0c5c7`. Without `lib/lufa` the build fails: `fatal error: lib/lufa/LUFA/Drivers/USB/Class/Common/HIDClassCommon.h: No such file or directory`, from `modules/zsa/oryx/oryx.c`. ZSA's Oryx module includes LUFA's HID headers even on ChibiOS. A shallow init of these five is enough. `lib/googletest`, `lib/lvgl`, `lib/pico-sdk` and `lib/vusb` aren't needed.
4. **The modules come from the fork's own submodule.** `keymap.json`'s `"modules": ["zsa/oryx", "zsa/defaults"]` resolve against `modules/zsa`, so no separate checkout is needed.
