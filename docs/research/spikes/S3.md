# S3: What BK's Oryx export contains

Run 2026-10-15. BK's Moonlander layout "Synchronized" is public on Oryx (`QxKPz`; GraphQL reports `privacy: false`). Its latest revision is `zLQ3Md`, `qmkVersion` `25.0`, which matches the pinned `firmware25` fork (D-040).

```
curl -sL -o oryx-QxKPz-zLQ3Md-source.zip https://oryx.zsa.io/source/zLQ3Md
sha256 cb9393a08aed0130295685f3c726db257bf510fff42356c5d369efe34936b092
```

The zip holds `README.md`, `build.log`, `zsa_moonlander_reva_QxKPz.bin`, `zsa_moonlander_revb_QxKPz.bin` (each with an `.md5`) and `zsa_moonlander_synchronized_source/` with `config.h` (10 lines), `keymap.c` (347 lines), `keymap.json` (7 lines) and `rules.mk` (7 lines). The source is committed as the importer fixture at `test/fixtures/oryx/synchronized/`.

## What's in it

- **Layers.** Six `LAYOUT_moonlander(...)` layers of 72 keys each.
- **Hold-taps.** `MT(MOD_LALT, KC_S)`, `MT(MOD_LGUI, KC_F)`, `MT(MOD_RGUI, KC_J)`, `MT(MOD_RALT, KC_L)`, `MT(MOD_LCTL, KC_Z)`, `MT(MOD_RCTL, KC_SLASH)`, `ALL_T(KC_G)` and `ALL_T(KC_H)` (Hyper), `MT(MOD_LALT, KC_APPLICATION)` and `MT(MOD_LCTL, KC_ESCAPE)`.
- **Layer keys.** `LT(n, kc)`, `MO`, `TO`, `TG`, `OSL`.
- **One-shot modifiers.** `OSM(MOD_LSFT)` and `OSM(MOD_RSFT)`.
- **Modified keys.** For example, `LALT(LGUI(LCTL(LSFT(KC_SPACE))))` and `LGUI(LSFT(KC_4))`. Shifted aliases such as `KC_EXLM`, `KC_LCBR` and `KC_TILD`. `KC_HYPR` and `KC_MEH`.
- **Other keys.** Mouse keys (`KC_MS_BTN1..3`, `KC_MS_LEFT…`). RGB keys (`RGB_MODE_FORWARD`, `RGB_TOG`, `RGB_HUD`, `TOGGLE_LAYER_COLOR`, the custom `RGB_SLD`). `QK_BOOT`.
- **A key with custom behaviour.** `#define DUAL_FUNC_0 LT(5, KC_4)` is intercepted in `process_record_user`. A tap sends F5 and a hold does `layer_move(5)`.
- **Tap dances.** `TD(DANCE_0)` and `TD(DANCE_1)` are Oryx's generated `ACTION_TAP_DANCE_FN_ADVANCED`. A single tap sends Hyper+Space or Alt+Space, and a double tap sends `[` or `]`.
- **Macros.** `ST_MACRO_0..3` are `SEND_STRING(...)` with `SS_TAP`, `SS_LGUI(SS_LSFT(...))` and `SS_DELAY(100)`.
- **Combos.** Eight combos, defined by keycode, not by position. For example, `{ MT(MOD_LALT, KC_S), KC_D }` gives Left Shift, and `{ KC_C, KC_V }` gives `ST_MACRO_1`. `config.h` has `COMBO_COUNT 8`.
- **Chordal Hold.** `CHORDAL_HOLD` and `PERMISSIVE_HOLD` in `config.h`, with a `chordal_hold_layout` handedness array of `L` and `R` per position.
- **Layer state.** `LAYER_STATE_8BIT` in `config.h` caps this layout at 8 layers.
- **RGB.** A per-layer `ledmap` indexed by layer number (`[1]`, `[2]`, `[4]`, `[5]`). `rgb_matrix_indicators_user` switches on `biton32(layer_state)` with `case 1:` and so on, and uses `rawhid_state` and `keyboard_config` from ZSA's module.
- **Modules.** `keymap.json` is only `{"modules": ["zsa/oryx", "zsa/defaults"]}`, ZSA's community modules, so a build needs `zsa/qmk_modules` beside the fork.
- **Identity.** `SERIAL_NUMBER "QxKPz/zLQ3Md"`.

## Conclusions for the importer and generator

1. Oryx's export is regular enough for tree-sitter C, as the blueprint planned (D-041). Every binding is a call expression or identifier inside `LAYOUT_moonlander(...)`.
2. **QMK combos are keycode-based.** The importer resolves each combo key to the base-layer position whose binding produces it. Combos import with `layerIds: "all"`. The generator writes the base-layer bindings at those positions back as keycodes. Recorded as a constraint in [../../blueprint/05-firmware-qmk.md](../../blueprint/05-firmware-qmk.md).
3. **Passthrough refers to layer indices.** The `ledmap`, `case n:`, `LT(5, …)` inside `DUAL_FUNC_0` and `layer_move(5)` all do. Until the generator can rewrite them, removing or reordering layers on a layout with layer-indexed passthrough must be a validator error (`passthrough_layer_index`). Adding a layer at the end is safe.
4. **The layer cap.** `LAYER_STATE_8BIT` limits this layout to 8 layers. The validator reads the setting.
5. **Not modelled, kept as `native`.** These become `native` bindings with their source kept: `OSM`, `TD(...)`, `DUAL_FUNC_0`, mouse keys, RGB keys and `QK_BOOT`. The tap-dance functions, the `DUAL_FUNC_0` case, the RGB code, `chordal_hold_layout`, `keymap.json` and the `SERIAL_NUMBER` define are kept as `Passthrough`.
6. **`ST_MACRO_0..3` import as `Macro`.** They match Oryx's `SEND_STRING` pattern.
7. **`KC_HYPR` and `KC_MEH`** import as `modifier` with four and three mods. `ALL_T(kc)` imports as a `holdTap` whose hold is all four left mods.
8. **For rung 3:** layer 2 already has `KC_LEFT_ALT` on the S position, and it's reached by holding Space (`LT(2, KC_SPACE)`) or `'`. Holding Space and tapping S twice may already give Option–Option. The rung 3 demo should check this before proposing changes.
