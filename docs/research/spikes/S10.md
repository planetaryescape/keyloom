# S10: the QMK importer runs inside a `bun build --compile` binary

Run 2026-10-15 on the importer commits of branch `rung1/core-import` (rebased afterwards onto `origin/main` `da2347e`; no source file changed by the rebase), bun 1.3.14, macOS arm64.

The importer parses `keymap.c` with `web-tree-sitter` and `tree-sitter-c`, which are two `.wasm` files. The question was whether a compiled executable can load them with no files beside it. It can, and so can the SQL migrations and the `boards/` folder.

## What embeds what

| Needed at runtime | How it's embedded | Where |
|---|---|---|
| `web-tree-sitter/web-tree-sitter.wasm` and `tree-sitter-c/tree-sitter-c.wasm` | `import x from "…wasm" with { type: "file" }`, read with `Bun.file(x).arrayBuffer()` and passed to `Parser.init({ wasmBinary })` and `Language.load(bytes)` | `src/firmware/qmk/c-parse.ts` |
| SQL migrations | `import sql from "….sql" with { type: "text" }` | `src/persistence/migrations.ts` |
| `boards/**/board.json`, `geometry.json`, `SKILL.md` | a Bun macro (`with { type: "macro" }`) that reads `boards/` at bundle time and inlines it | `src/boards/embedded.macro.ts`, `src/boards/registry.ts` |

The WASM is passed as bytes, not as a path. In the compiled binary the imported value is a path inside Bun's virtual filesystem (`/$bunfs/root/tree-sitter-c-eqwk7pgq.wasm`), and `Bun.file()` reads it. Emscripten's own file loading doesn't know that filesystem, which is why `wasmBinary` is given directly.

## Conclusion and what the release build needs

1. The release build needs no extra flags and no files beside the binary: `bun build --compile --target=bun-<os>-<arch> src/cli/main.ts --outfile keyloom` embeds the WASM, the SQL and the boards through the imports above. W2's server entry must sit on top of `src/cli/main.ts` (or import `src/app`) so the same modules are bundled; any new entry file that uses the importer gets the embedding for free, because it is done by the imports in `c-parse.ts`, not by the build command.
2. Don't replace those imports with `new URL(…, import.meta.url)` or a path built from `import.meta.dir`: that works under `bun run` and fails in the binary.
3. The `boards/` macro reads the folder next to `src/boards/` at bundle time, so the build must run in a checkout that has `boards/` (it does not use the current directory).
4. Adding a board needs no code change; adding a migration needs the `.sql` file and one line in `src/persistence/migrations.ts` (a test fails if they disagree).
5. `bun build --compile` can leave a `.<hash>.bun-build` file in the working directory. Ignore it in `.gitignore` or delete it after the build.
