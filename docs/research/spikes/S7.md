# S7: Glove80 build time in Docker and Nix

Run 2026-10-15 on BK's Mac (Docker 28.4.0, arm64). Template `moergo-sc/glove80-zmk-config@34888be8c9d9a3d5b168a502b8b191ba43b4a1f3`, firmware `moergo-sc/zmk@ce69e85f585c724142aae37ddf8a7e019ff19e93` (`v26.09`), and the template's default `config/glove80.keymap`.

## MoErgo's own Dockerfile ran out of space

`./build.sh v26.09` failed while building the image, with `cp: cannot create directory 'zephyr': No space left on device`. The Dockerfile pre-builds the Nix store for `main` *and* the last three tags. BK's Docker Desktop VM disk is 156.9G and was 99% full, with 1.1G free. The cause is the machine's Docker disk, not the template, but anyone with a tight Docker disk will hit it.

## keyloom's lean image builds one pinned ref

`infra/glove80/Dockerfile` (committed) pre-builds only the pinned `moergo-sc/zmk` ref. It used about 11G of free space after `docker builder prune -f`.

| Step | Wall time | Notes |
|---|---|---|
| Image build (first time) | 163 s | Image is 5.22 GB. Toolchain comes from the `moergo-glove80-zmk-dev` Cachix cache |
| Firmware build 1 | 20 s | `building zmk_glove80_lh.drv`, `zmk_glove80_rh.drv`, `combined_…drv` |
| Firmware build 2 | 16 s | Same three derivations rebuilt. Each `--rm` container starts with the image's store, so this is a real compile, not a cache hit |

The output is one `glove80.uf2` of 819,200 bytes (two images joined end to end).

## What changes

- The build fits an edit-and-try loop: under 20 s once the image exists.
- keyloom ships `infra/glove80/Dockerfile`, builds the image once with the pinned ref in its tag, and runs `docker run --rm -v <workspace>:/config -e UID -e GID <image>`.
- `keyloom doctor` checks free space inside Docker's VM (`docker run --rm alpine df /`) and warns below 15G, with the fix (`docker builder prune`, or raising Docker Desktop's disk limit).
