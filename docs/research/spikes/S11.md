# S11: Zapp under keyloom's control (partial; no keyboard attached)

Run 2026-10-15 with zapp 1.0.2 (`brew install zapp`, `/opt/homebrew/bin/zapp`). No ZSA device was connected: `system_profiler SPUSBDataType` matched nothing for `zsa`, `moonlander`, `stm32` or `3297`. So nothing could be flashed.

## Observed

- The whole CLI is `zapp flash <FIRMWARE>`, `zapp update` and `zapp help`. There's no device listing, no timeout flag and no machine-readable output.
- **Zapp checks the file before it looks for a device.** A file without a DFU suffix or Intel HEX header fails immediately with exit 1 and `Invalid firmware: not a valid firmware file (no DFU suffix or Intel HEX header found)`. A missing file also exits 1, with `IO error reading … No such file or directory`.
- **keyloom's Docker builds carry the DFU suffix** (S5), the same as Oryx's own builds. The last 16 bytes encode the target bootloader: reva `0483:df11` and revb `3297:2003`. Only the CRC differs from Oryx's binaries.
- **With a valid file and no keyboard,** zapp prints `Firmware loaded: STM32 DFU (67252 bytes)` and then waits silently. It printed nothing in 8 s, and SIGINT didn't end it. SIGTERM did (exit 143).

## What keyloom does with this

- keyloom picks the binary for the board's detected revision. The suffix names the bootloader the binary is for, so a wrong-revision binary is caught before flashing, whether or not Zapp checks it too.
- keyloom enforces its own timeout: 120 s after `Firmware loaded`, it sends SIGTERM and reports "No Moonlander in bootloader mode was found". It treats `Firmware loaded` as the signal to show the "press the reset button" instruction.

## Seen since (2026-10-22, BK's Moonlander)

- On success zapp prints nothing after `Firmware loaded` and exits 0. Three hands-free flashes in `~/.local/share/keyloom/logs/` (`flash-fl_01M5GPYDR82XT7CVG754SGXNTG.log`, `flash-fl_01M5JC2HWQDWYDPPGE5BN3KK1C.log`, `flash-fl_01M5K41CQ8N3DZ5E8HKDYVHP44.log`) each go `Firmware loaded` → keyloom's "the keyboard is in its bootloader (0483:df11)" → `zapp exited 0`. The write starts when the bootloader appears and makes no output, so keyloom takes the bootloader on USB as the start of the write (D-503).
- Not observed: a manual-reset flash's log, or what zapp prints on a mid-flash failure.
